# devops开发相关

代码方面：使用django进行后端服务的构建，然后一些重要的配置会放到k8s集群上的ConfigMap，密码变量会存放再Secret，一定要写好Jenkinsfile还要dockerfile。

push分支到GitLab上，提交MR并审查通过合并到开发分支，被GitLab的webhook自动触发Jenkins流水线（需要先在Jenkins上面进行配置Jenkinsfile的存放位置），部署到测试环境上面去，由于为了方便，使用了StatefulSet管理Pod。

上面的流程，大概就是这么一个CICD的过程，** CI**：GitLab Webhook 通知 Jenkins，Jenkins 拉代码、跑测试、构建 Docker 镜像。** CD**：Jenkins 把镜像推到镜像仓库，然后通过 K8s 部署到测试环境。

日志收集一般使用ELK，监控用的是Prometheus+Grafana

devops就像是一个环，可以快速敏捷地开发

#### 左半环：Dev（开发侧）

1. **规划（Plan）**：环的起点，也是上一轮循环的终点
   输入是上一轮循环的反馈（线上 Bug、用户需求、监控发现的性能问题、业务迭代目标），输出是迭代计划、需求拆分、技术方案。对应你的场景：测试环境测出 Django 接口 Bug、产品提了新的后端接口需求，都会回到这一步，规划下一轮开发。
2. **开发（Code）**：开发落地环节
   基于规划的需求，本地开发 Django 代码、切功能分支、单元测试编写，最终把代码推送到 GitLab 分支。
3. **构建（Build）**：CI 的核心环节
   代码提交后，通过自动化流水线完成代码检查、依赖安装、单元测试、打包构建。比如我的场景：GitLab 合并代码后，Webhook 触发 Jenkins，执行 Jenkinsfile 里的步骤，用 Dockerfile 把 Django 应用打包成标准化容器镜像，完成构建。
4. **测试（Test）**：持续交付的前置校验
   把构建好的版本自动部署到隔离环境，完成自动化集成测试、接口测试、性能测试、人工功能验收。比如我的场景：Jenkins 流水线自动把镜像部署到 K8s 测试环境，也方便给前端联调。

#### 右半环：Ops（运维侧）

5. **发布（Release）**：版本发布
   把经过测试验证的、可信的镜像版本，通过标准化流程发布到生产环境，通常用 K8s 的滚动发布、蓝绿发布、金丝雀发布来保证发布过程零停机。
6. **运维（Operate）**：生产环境的稳定保障
   负责生产环境的运行管理，包括 K8s 集群管理、Pod 生命周期管理、扩缩容、配置管理、故障自愈。对应你的场景：用 StatefulSet/Deployment 管理 Django 的 Pod，用 ConfigMap/Secret 管理配置和敏感信息，保证服务稳定运行。
7. **监控（Monitor）**：全链路可观测
   7×24 小时监控服务的运行状态，包括接口可用性、响应时间、错误率、资源占用、业务数据、日志异常，常用 Prometheus+Grafana、ELK 等工具，捕捉线上问题和性能瓶颈。
8. **反馈（Feedback）**：环的闭合点，也是下一轮循环的起点
   把监控发现的问题、用户的反馈、业务数据的变化、安全漏洞、性能瓶颈全部收集汇总，**重新送回第一步的「规划」环节**。比如监控发现 Django 的某个查询接口响应超时，就会规划性能优化需求，重新开启一轮完整的循环。
